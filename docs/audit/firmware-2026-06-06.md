# Firmware Audit — Speed Pyramid live puck firmware (2026-06-06)

Area **D — Firmware** from `AUDIT-PROGRAM.md`. Highest-stakes area (pucks in
the field; field fixes need physical USB access). Ran the standard playbook:
4 parallel adversarial review agents (network resilience, memory/parsing
safety, state-machine correctness, secrets/OTA/build), then re-graded every
finding against the real code **and the server it talks to** (`pair_routes.py`).

## Scope — what is actually LIVE

The only firmware built for the field is the Speed Pyramid path, compiled by
the `puckN_speed_pyramid` / `puckN_dev_speed_pyramid` platformio envs via
`build_src_filter = -<*> +<firmware/sp_main.cpp>`:

- `src/firmware/sp_main.cpp` — entry (`setup`/`loop`)
- `src/games/g_speed_pyramid.h` — the whole game state machine + HTTP glue
- `src/hal/sp_net.h` — WiFi + HTTP
- `src/hal/sp_imu.h` — MPU-6050 tilt/quadrant
- `src/hal/sp_button.h` — debounced button (TAP / HOLD_1S / HOLD_3S)
- `src/hal/sp_led.h`, `sp_feedback.h`, `sp_pins.h`

**Explicitly out of scope (legacy, not in any build filter):** `src/main.cpp`,
`main_tablewars.h`, `main_complete.h`, `main_tablewars_v2_UPGRADED.h`,
`tv_games.h`, `dual_core.h`, `esp_now_multiplayer.h`, `capacitive_touch.h`,
`ota_update.h`, `ota_manager.h`, `i2s_audio.h`, `bluetooth_audio.h`,
`camera_module.h`, `sd_card.h`, `src/archive/*`. These are audited only where
they bear on the live path (OTA / secrets, below).

## Findings by tier (re-graded)

### HIGH

**H1 — Live pucks are ghost-swept ~30s into a match (firmware never heartbeats).**
`server/pair_routes.py` treats the match-state poll as "our natural heartbeat
channel" **only when the caller passes `?puck_id=<n>`** (`_bump_last_seen`,
pair_routes.py:1529-1532), or via `POST /api/sp/heartbeat` (pair_routes.py:2465).
The firmware does **neither** — `_poll_match_state_complete` /
`_poll_pending_pick` / `_poll_pending_minigame` all GET
`/api/sp/match-state/<code>` with no query arg (g_speed_pyramid.h:233,247,295),
and there is no `/heartbeat` call anywhere. A puck's `last_seen` is therefore
frozen at join time (pair_routes.py:197,339). `_sweep_stale_pucks` runs on every
match-state GET and every reveal attempt and drops any expected puck older than
`GHOST_TIMEOUT_S = 30` (pair_routes.py:526,540-571), emitting `player_left`
(reason "ghost"). Net: a still-connected puck is falsely removed from
`expected_pucks` ~30s in — including single-puck games. **Fix:** send
`?puck_id=PUCK_ID` on the match-state poll. Folded into the consolidation in H2.

**H2 — Three GETs to the same endpoint per 500ms tick.**
Every in-game poll tick calls `_poll_match_state_complete()`,
`_poll_pending_pick()`, and `_poll_pending_minigame()` — each a **separate,
blocking** GET to the *same* `/api/sp/match-state/<code>` (g_speed_pyramid.h:
231-316, dispatched at 658-690). 3× the server round-trips, 3× the
`http.getString()` heap churn, 3× the blocking window. **Fix:** one
`_poll_match_state()` that fetches once (with `?puck_id=`) and parses
`complete` / `pending_category_pick` / `pending_minigame` from the single body.

**H3 — No WiFi reconnection.** `sp_net::connect()` runs once at boot
(sp_main.cpp:31 → g_speed_pyramid.h:457); nothing re-attempts a connect if WiFi
drops. `is_connected()` then gates every request and returns false forever
(sp_net.h:39-41,47,80), so a puck that loses the AP is dead until power-cycle
unless the IDF happens to self-heal. **Fix:** `WiFi.setAutoReconnect(true)` in
`connect()` plus a throttled `ensure_connected()` reconnect attempt from the
main loop.

**H4 — Hardcoded WiFi + OTA secrets in git-tracked `platformio.ini`.** Real bar
SSID/password are baked into four build envs (`platformio.ini:100-101,118-119,
140-141,164-165`) and the legacy OTA password `puck2024` at `platformio.ini:60`.
Bar-LAN threat model keeps this out of CRITICAL, but: the creds are in git
history forever, shared with every contributor/CI artifact, and cannot be
rotated without a rebuild + re-flash of every puck. **Fix (repo hygiene):**
move them to a gitignored `secrets.ini` pulled in via `extra_configs`, ship a
`secrets.ini.example`, ignore `secrets.ini`. Rotating the live password and
rewriting history are manual ops (flagged below, not done here).

**H6 — Production build envs can't compile from a clean checkout (missing
`lib_deps`).** Found while compile-verifying the fixes: `puck1_speed_pyramid` /
`puck2_speed_pyramid` — the envs flashed to the *bar* pucks — declared **no
`lib_deps`**, so PlatformIO's LDF cannot locate FastLED / Adafruit MPU6050 and
`pio run -e puck1_speed_pyramid` aborts at `#include <Adafruit_MPU6050.h>`.
Only the `*_dev_*` envs carried the deps, which is why dev builds worked and
the gap went unnoticed. Net: you cannot build/flash a production puck from a
fresh clone. **Fix:** add the same pinned `lib_deps` block to both production
envs. Verified `pio run -e puck1_speed_pyramid` → SUCCESS after.

**H5 — Answer POST failure silently swallows the player's answer.**
On TAP in ANSWERING, the puck always transitions to LOCKED whether or not the
POST landed (g_speed_pyramid.h:829-834): `_post_answer` is called, and
`_state = IN_GAME_LOCKED` runs unconditionally right after. A transient network
blip = the answer is lost with zero feedback. The server answer endpoint is
idempotent (`409 "already answered"`, pair_routes.py:2251), so a retry is safe.
**Fix:** on POST failure, play a distinct error buzz and **stay in ANSWERING**
so the player can re-tap before the browser-driven timer force-reveals.

### MEDIUM

**M1 — Blocking HTTP timeout is 5s.** `http.setTimeout(5000)` (sp_net.h:56,90).
The loop is `pair_mode_loop(); delay(8)`, so a stalled request freezes
button+IMU for up to 5s and drops taps. **Fix:** drop to 3s — still generous
for a LAN Flask, less dead time. (Combined with H2, worst-case per-tick stall
goes from 3×5s to 1×3s.)

**M2 — Brittle hand-rolled JSON parsing.** Magic offsets `pp_at + 24` /
`mg_at + 19` (g_speed_pyramid.h:254,301) are correct today but silently break if
a key is renamed; `_extract_string` has no length bound (142-151); `time_limit_s`
is multiplied by 1000 with no clamp (391). None are reachable exploits against
the trusted LAN server, but they are fragile. **Fix:** extract the pure parsers
to `src/hal/sp_json.h`, replace magic offsets with `needle.length()`, bound
extracted-string length, clamp `time_limit_s`. Ship a host-compiled unit test
(first firmware test harness).

**M3 — No failure feedback on `start` / `select-category` / `reset` / `cancel`.**
`_post_start` failure only logs (g_speed_pyramid.h:612-614); `_post_select_category`
/ `_post_reset` failures leave the player in place with at most a red flash
(721-725, 854-860); `_post_cancel` failure still drops to IDLE while the server
keeps the lobby (571-577,598-605). The player can't tell a no-op from a network
miss. These self-heal (the poll re-derives state; answer/cancel are idempotent
or TTL'd), so not HIGH — but a beep/flash on failure removes the guesswork.
**Fix:** add error feedback; leave state transitions as-is where the poll
recovers.

**M4 — `HOLD_3S` fires at 5000ms, but the enum name + header comment say 3s.**
sp_button.h:77 checks `held >= 5000`; the file header (lines 5-7) documents
`HOLD_3S (held >= 3000ms)`. Either the threshold drifted or it was deliberately
stiffened to resist accidental cancels (see the mid-dial-cancel note,
g_speed_pyramid.h:565-568). **Fix:** make it a named constant with an honest
comment; **behavior preserved at 5s** pending a product call on the intended
duration (flagged below).

### LOW

**L1 — `_pick_idx` not reset on leaving CATEGORY_PICKING** (g_speed_pyramid.h:
671-674). A stale index carries into the next pick round; the `chosen > 0`
guard (719) prevents an out-of-bounds commit, so it's cosmetic. **Fix:** reset
on exit.

**L2 — Floating (`^`) lib_deps** (platformio.ini:29-34) — a rebuild can pull a
newer minor/patch of FastLED/Adafruit/ArduinoJson. Supply-chain hygiene.
**Fix:** pin exact versions.

**L3 — Fallback creds `TableWars`/`tablewars`** in sp_net.h:18-24 — only used if
build_flags omit the defines, which the live envs never do. Defense-in-depth
nit; left as-is.

## Re-graded DOWN / rejected (agent findings that did not survive triage)

Recorded for honesty — these were flagged (some as "CRITICAL") and are **not**
real:

- **`"id"` substring matches inside `"category_id"`/`"puck_id"`** (claimed
  CRITICAL): false. The search needle is `"id":` *with the leading quote*
  (g_speed_pyramid.h:269); `category_id`/`puck_id`/`question_id` contain `_id`,
  not `"id`, so they never match. The parser only hits a field literally named
  `id`.
- **`millis()` underflow in `_show_pair_mode_glow` / lobby poll / minigame fire**
  (claimed CRITICAL ×3): false. `now - last` on `uint32_t` is the standard
  rollover-safe Arduino idiom — modular arithmetic yields the correct elapsed
  value across the 49.7-day wrap. The one guarded site (g_speed_pyramid.h:788)
  is guarding a *logic ordering* issue (a timestamp set newer than a previously
  sampled `now`), not rollover.
- **Timeout path doesn't notify the server → round hangs** (claimed HIGH):
  by design. The browser's `QuestionScreen` owns the timer and calls
  `POST /api/sp/force-reveal` on expiry (QuestionScreen.tsx:96,210; api.ts:173).
  The puck deliberately stays silent (g_speed_pyramid.h:798-799).
- **Stale `_current_question_id` lets a late TAP double-submit** (claimed LOW):
  false. In LOCKED the ANSWERING TAP branch isn't taken (it's `if ANSWERING {…}
  else glow`), so no stale `_post_answer` fires.
- **Per-digit `/api/pair/dial` failure desyncs the code** (claimed HIGH):
  overstated to LOW. `_post_confirm_v2` sends the full 6-digit code as the source
  of truth (g_speed_pyramid.h:155-160); per-digit dial/preview POSTs only drive
  the TV display.

## Verified solid (keep)

- Unsigned-millis ordering guard at g_speed_pyramid.h:788-795.
- Post-TAP IMU lockout with zero-guard (g_speed_pyramid.h:514-516).
- Button debounce edges + HOLD_1S-then-HOLD_3S laddering (sp_button.h:52-104).
- IMU I²C bus recovery before `Wire.begin()` and 3× `mpu.begin()` retry
  (sp_imu.h:53-101) — genuinely good hardware fault tolerance.
- Tilt re-arm latch + 350ms cooldown to kill wobble-back (sp_imu.h:42-156).
- Edge-triggered preview POSTs (only on quadrant change) to avoid flooding.
- `show_quadrant` masks the index `q & 0x3` and early-returns on `q < 0`
  (sp_led.h:94-106) — bounded.
- Per-(puck,question) idempotency on the server answer path makes firmware
  retries safe (pair_routes.py:2251).

## Deliberately deferred (with rationale)

- **NVS runtime WiFi/server provisioning** — removes the re-flash-on-network-
  change pain (and H4's rotation cost), but it's a real feature (AP mode,
  captive config, NVS storage). Out of scope for a hardening pass.
- **HTTPS/TLS + request HMAC** — bar-LAN threat model is low-value; TLS on the
  ESP32 to a local Flask means cert management on both ends for modest gain.
  Documented; revisit if pucks ever talk off-LAN.
- **Secure signed OTA / OTA in the live build** — the live firmware has *no*
  OTA at all, so field updates are USB-only. That's a security win (no
  unauthenticated LAN flash surface) but an ops cost. Treating USB-only as the
  intended posture for now; the legacy `ota_update.h` (MD5-only, shared
  `puck2024` password) stays out of the live path. If OTA is ever added it must
  be signature-verified — not MD5.
- **IMU re-arm vs. held-tilt, deadzone hysteresis** — real edge cases (a puck
  held at a fixed angle between RETURN_NEAR_ZERO and FIRE won't re-arm; boundary
  flicker spams preview POSTs), but tuning these blind risks regressing feel.
  Needs hardware-in-the-loop. Deferred to a bench session.
- **Polling jitter/backoff (thundering herd)** — negligible at 2–6 pucks.
- **git-history scrub + live WiFi password rotation** — manual ops decisions for
  the owner; see manual items.

## Resolution summary

**Fixed (live firmware builds verified: `pio run -e puck1_speed_pyramid` and
`-e puck1_dev_speed_pyramid` both SUCCESS; host tests green):**

- **H1 + H2** — `g_speed_pyramid.h`: the three per-tick GETs to
  `/api/sp/match-state` collapsed into one `_poll_match_state()` that fetches
  once **with `?puck_id=`** (heartbeats the puck so it's no longer ghost-swept)
  and fills complete/pick/minigame from the single body. Side benefit: a failed
  match-state GET now holds state instead of falling through and kicking the
  picker back to IDLE.
- **H3** — `sp_net.h` + `sp_main.cpp`: `WiFi.setAutoReconnect(true)` in
  `connect()`, plus a throttled non-blocking `ensure_connected()` called each
  loop so a dropped link re-associates instead of stranding the puck.
- **H4** — secrets pulled out of git-tracked files into a gitignored
  `secrets.ini` (`extra_configs`), with `secrets.ini.example` committed and a
  `.gitignore` entry. Real WiFi creds / OTA password also scrubbed from the
  legacy `src/archive/server_comm.h`, `src/ota_update.h`, and `AGENTS.md`.
  `git ls-files | grep` for the old creds now returns nothing.
- **H5** — `g_speed_pyramid.h`: a failed answer POST no longer silently locks;
  it buzzes an error and stays in ANSWERING for a retry (safe — server answer
  endpoint is 409-idempotent).
- **H6** — `platformio.ini`: added the missing pinned `lib_deps` to both
  production envs so a clean checkout can build/flash bar pucks.
- **M1** — HTTP timeout 5s → 3s (`sp_net.h`), bounding the per-request freeze.
- **M2** — pure JSON extractors moved to `src/hal/sp_json.h`: bounded
  `extract_string`, needle-derived `value_offset`/`value_is_null` (magic
  `+24`/`+19` gone). First firmware **host test harness** added
  (`testing/firmware/`, wired into CI) covering the extractors + the
  pending-pick "id" false-positive defense.
- **M3** — failure feedback (buzz + red flash) on `start` / `select-category`.
- **M4** — `sp_button.h`: long-hold threshold is now the named `kLongHoldMs`
  with an honest comment; behavior preserved at 5s pending the product call.
- **L1** — `_pick_idx` reset on leaving CATEGORY_PICKING.
- **L2** — `lib_deps` carets (`@^`) pinned to exact versions across all envs.

**Deferred** — as listed above (NVS provisioning, TLS/HMAC, signed OTA / the
USB-only update posture, IMU re-arm & deadzone hysteresis, polling jitter).

**Manual follow-ups for the owner** — rotate the bar WiFi password (it remains
in git history), optionally scrub history, and confirm the intended long-hold
duration (3s vs the shipped 5s).
