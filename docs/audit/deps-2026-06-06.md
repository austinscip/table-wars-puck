# Dependency CVE audit (2026-06-06)

Closes **POST-SWEEP-FOLLOWUPS #2**. The first sweep claimed "deps pinned" but
never ran a CVE check. This is that check — `pip-audit` (server) + `npm audit`
(portal / TableWarsTV / speed-pyramid), triaged, with behaviour-relevant bumps
verified against the full server suite + an app-boot smoke (not blind bumps).

## Server (`server/requirements.txt`) — fixed

`pip-audit` on the installed env surfaced real CVEs. Bumped to patched floors:

|---|---|---|---|
| Flask | 3.0.0 | 3.1.3 | CVE-2026-27205 |
| Werkzeug | *unpinned* (transitive) | >=3.1.6 | CVE-2026-21860, CVE-2026-27199 (multipart-DoS class) |
| flask-socketio | 5.3.5 | 5.6.1 | — (see note) |

**flask-socketio is the load-bearing one.** The Flask 3.0→3.1 bump is required
for the Flask CVE, but Flask 3.1 made `RequestContext.session` a read-only
property, which **crashes flask-socketio 5.3–5.5 on every socket event** (its
`manage_session` path does `ctx.session = ...`). `app.py` constructs `SocketIO`
with `manage_session` defaulting on, so this would have broken every emit in
prod. flask-socketio **5.6.1** fixes it. A real cross-dependency interaction
caught only because the bump was test-verified, not blind — `test_socketio_emit`
(real Flask-SocketIO server + room membership) failed on 5.4.1/5.5.1 and passes
on 5.6.1.

**eventlet removed, not bumped:** it was referenced only in a stale `app.py`
comment. The deploy runs the gevent worker (`GeventWebSocketWorker`) and SocketIO
is `async_mode="threading"`; nothing imports eventlet. Dropping it removes the
dep and its CVE surface outright (comment in `app.py` corrected).

Verified: full server suite **264 passed**, CI-scoped mypy clean, `import app`
boot smoke OK on the upgraded stack. (`gunicorn`/`gevent` are deploy-only and
don't build on the local Python 3.14; they aren't imported by the suite, so the
pins are applied but exercised only in the prod image.)

## Residuals — deferred with rationale

- **Pillow image-parse CVEs (12.x)** — floor raised to `>=11.3.0` to pull the
  non-parse fixes; the remaining CVEs are all malicious-**image-parsing**.
  Pillow is used here **only to generate** QR-code PNGs from our own trusted
  data — there is no untrusted-image decode path — so these are not reachable.
  Owner may pin `>=12.2.0` for cleanliness if desired.
- **`pip` CVEs** — `pip` is not a runtime dependency; build-tooling only.

## JavaScript

- **TableWarsTV** — `npm audit`: **0 vulnerabilities**.
- **speed-pyramid web TV** — `npm audit`: **0 vulnerabilities**.
- **portal (Next.js 16.2.7)** — 2 **moderate**, both `postcss` (CVE-2023-44270,
  CSS-parsing ReDoS) pulled transitively by every Next ≤16.3.0. **Deferred:**
  postcss runs at **build time** on the app's own CSS — there is no
  attacker-controlled CSS input, so the ReDoS isn't reachable at runtime. The
  fix requires either Next `>=16.3.0` (a minor bump) or a `postcss` override in
  `portal/package.json`; both need a portal build to verify, which isn't part of
  the server CI here. **Recommended owner action:** add
  `"overrides": { "postcss": ">=8.4.31" }` to `portal/package.json` and rebuild,
  or bump Next to `>=16.3.0`.
