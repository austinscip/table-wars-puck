   **directly** per-screen: web TV `lib/audio.ts` (sample + procedural
   fallback) + firmware `sp_led.h`/`sp_feedback.h` + per-question **narration

So the live-impacting findings are all in the **VO narration** path; the cue

## Findings by tier (re-graded)

### MEDIUM (live)

**P1 — Narration asset cache never invalidated; mis-drives live question
selection.** `pair_routes._NARRATED_QIDS_CACHE` was built once at first use and
never refreshed ("a server restart picks up new files"). But `_has_narration`
gates the **R027 question-substitution** logic (`pair_routes.py:1432-1445` —
an un-narrated question is swapped for a narrated alternative). So after an
operator regenerates narration on a **running** server: the new MP3s aren't
served, AND the substitution logic runs on stale data (questions that now have
narration are still avoided / vice-versa) until a restart. **Fixed:** the cache
now **auto-invalidates on the questions-directory mtime** — adding/removing a
`q_<id>.mp3` bumps the dir mtime, so a regen is picked up on the next call with
no restart. (Content overwrites don't change set membership; the per-file
`?v=<mtime>` cache-bust in `_narration_url` already handles those.) Also added a
**`_MIN_NARRATION_BYTES` floor** so a 0-byte/truncated MP3 from a crashed TTS
run isn't counted as narration (it would otherwise be "served" as silence or a
stalled load). Regression-tested.

**P2 — A stalled narration fetch can wedge the question screen forever.**
`QuestionScreen` started the answer countdown only on the narration audio's
`ended`/`error`/`loadedmetadata` events. On flaky bar WiFi a fetch can stall so
**none** of those fire, leaving the screen stuck in `awaiting_question` (frozen
timer) until a human reloads. **Fixed:** an absolute 15s `STALL_GUARD_MS`
safety timer (tracked in `narrationTimersRef`, cleared on reveal/unmount) forces
the handoff so the round always becomes answerable. `handoff` is idempotent, so
it's a no-op when narration played normally.

### LOW / build-time

**P3 — Generation scripts can leave partial/corrupt MP3s.**
`generate_narration*.py` write directly to the final `q_<id>.mp3` path, so a
crashed ffmpeg/TTS run can leave a truncated file. The live impact is now
bounded by P1's size floor (truncated → treated as no-narration) + P2's stall
guard, so the runtime is safe regardless. The root-cause fix (write to a temp
file + atomic rename) is a clean build-script change but lower priority —
**deferred** (noted).

## Re-graded DOWN / rejected (cue-dispatch agent)

The cue-dispatch agent raised several "CRITICAL"s; none are real current bugs:

- **"Post-recovery `cue_seq` watermark collision"** — false. `cue_seq` is
  persisted and restored (`match.py:181`); recovered cues resume with
  `seq > lastSeq`, so the TV fires them. Covered by `test_cue_watermark.py` +
  `test_match_recovery.py`.
- **"MATCH_RESET doesn't reset the seq"** — about an **unbuilt** rematch
  feature; the agent admits "MATCH_RESET is defined but never emitted by any
  game." Not reachable.
- **"Empty `channels: []` silently broadcasts"** — no game emits `channels=[]`
  (the convenience constructors use `null` or a specific tuple). Speculative.
- **"Idempotency replay / cloud-failover seq inversion"** — local and cloud
  carry the **same** `snapshot_seq` for the same frame by construction (ADR
  0004), so there's no inversion. The agent also **self-retracted** its
  heartbeat-cue-race finding ("FALSE ALARM").
- **"Rapid-cue animation cancel" / "useEffect over-deps"** — about
  `TableWarsTV` (non-live, area B2) and the stubbed audio path; trivial polish
  nits, deferred to B2.

## Verified solid (keep)

- **Cue dispatch**: monotonic `cue_seq` stamped inside the per-match lock
  (`match.py:792-802`); TV `CueDispatcher` dedupes on `seq` (not wall-clock
  `ts` — correctly resilient to NTP steps), resets on `matchId` change, falls
  back to index for pre-seq snapshots. Covered by `test_cue_watermark.py` +
  `cues.test.ts`.
- **Live audio bus** (`audio.ts`): singleton AudioContext, bounded sample
  cache, procedural fallback when an MP3 is missing, `stopAll` on route change
  (audited in the TV pass).
- **Missing-narration handling**: `_narration_url` returns a path even when the
  file is absent; the TV treats the 404 as "no narration" and proceeds (now
  also guarded against stalls by P2).
- **Generation input safety**: question text is passed to Piper/Kokoro via
  **stdin**, not argv/shell — no injection.

## Deliberately deferred (with rationale)

- **Atomic-write in the generation scripts (P3)** — runtime impact already
  bounded by P1+P2; build-script hygiene, lower priority.
- **Cue-system payload `json.dumps` guard / `channels=[]` semantics / overlay
  `stopAnimation`** — defense-in-depth on the **non-live** next-gen cue client;
  fold into the B2 (`TableWarsTV`) pass.
- **SFX asset license manifest** — V1 ships procedural tones only; revisit when
  CC0 SFX are added.
