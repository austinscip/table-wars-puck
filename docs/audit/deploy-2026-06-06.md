# Deploy / Ops Audit (2026-06-06)

Area **Deploy / ops** from `AUDIT-PROGRAM.md` (🟡 partial — hardened during
runtime work; this is the dedicated pass). Surface: `Dockerfile`,
`docker-compose.yml`, `nginx/nginx.conf`, `tablewars.service` +
`deploy/tablewars-runtime.service`, the deploy/backup shell scripts,
`railway.json`. No fan-out — direct review (it's config, not code).

## Threat-model note

Two deploy shapes coexist:
- **Self-hosted bar box** (compose + nginx): pucks hit the app on **`:5001`
  directly** over the LAN (the firmware's `SERVER_URL` is `http://…:5001`), and
  nginx terminates TLS on 80/443 for the portal/public side. So the app's 5001
  host exposure is **required** and was NOT removed.
- **Railway** (Dockerfile only, single container, platform TLS).

## Findings by tier

### MEDIUM (fixed)

**D1 — `docker-compose.yml` shipped insecure default secrets.** `POSTGRES_
PASSWORD: ${DB_PASSWORD:-change_me_in_production}`, the same in `DATABASE_URL`,
and `SECRET_KEY: ${SECRET_KEY:-change_this_secret_key_in_production}` — the `:-`
defaults mean a direct `docker compose up` without the env set runs the **prod
DB and Flask with publicly-known credentials**. (`deploy_production.sh` greps
`.env` for these strings, but the compose-up path bypasses it.) **Fixed:**
switched to `${VAR:?…must be set}` so compose **fails closed** if the secret is
unset. Verified: `docker-compose config` exits 1 with the message when
`DB_PASSWORD`/`SECRET_KEY` are absent, OK when set.

**D2 — Postgres exposed to the host (`5433:5432`).** Nothing external talks to
the DB — the app reaches it over the internal `tablewars` bridge as
`postgres:5432`, and pucks hit the **app**, not the DB. The host port mapping was
pure attack surface (the DB reachable from the host/LAN). **Fixed:** replaced the
`ports` mapping with `expose: ["5432"]` (internal-only); a 127.0.0.1-bound
mapping can be re-added for ad-hoc admin, never a `0.0.0.0` one.

### LOW (fixed)

**D3 — Compose app healthcheck queried the DB** (`/api/stats`) — heavier and can
false-fail on DB latency, unlike the `Dockerfile`'s DB-free
`/api/runtime/health`. **Fixed:** compose now uses `/api/runtime/health` too.

**D4 — No `no-new-privileges` on compose containers.** The systemd unit has
`NoNewPrivileges`, but compose didn't. **Fixed:** `security_opt:
[no-new-privileges:true]` on db / app / nginx. Also dropped the obsolete
top-level `version:` key.

**D5 — `tablewars.service` restart-storm protection was silently disabled.**
`StartLimitBurst`/`StartLimitInterval` were in `[Service]`, but modern systemd
reads `StartLimitIntervalSec`/`StartLimitBurst` from `[Unit]` — so the
3-restarts-per-60s limit was ignored and a crash-looping unit would restart
forever. **Fixed:** moved them to `[Unit]` (as `StartLimitIntervalSec=60` +
`StartLimitBurst=3`).

**D6 — nginx missing `Referrer-Policy`.** Had HSTS / X-Frame-Options / nosniff /
X-XSS-Protection; added `Referrer-Policy: strict-origin-when-cross-origin`.

## Re-graded DOWN / rejected

- **"`deploy_all_pucks.sh` lacks `set -euo pipefail`"** — rejected; adding it
  would **break** the script. It intentionally continues past a failed/offline
  puck (per-puck try + a failure summary), references an unset `$1` (breaks
  `set -u`), and uses `((COUNT++))` which returns non-zero on the 0→1 increment
  (breaks `set -e`). Its error handling is correct as designed.
- **"systemd worker-class `eventlet` vs Dockerfile `geventwebsocket`"** — left
  alone. Both are valid Flask-SocketIO async workers (`app.py`'s own comment
  even names eventlet as the prod choice); changing it blind risks breaking the
  websocket path. Noted as a consistency item, not a fix.
- **nginx per-IP rate limiting** — deliberately NOT added: on the bar LAN every
  puck shares the venue's NAT'd public IP, so a per-IP `limit_req` would throttle
  all pucks as one client and break gameplay. (The unauthenticated game
  endpoints are mitigated by network isolation per `legacy-flask-2026-06-06.md`.)

## Verified solid (keep)

- **Dockerfile** — multi-stage, non-root `tablewars` user (uid 1000), gevent-
  websocket gunicorn worker, **`--workers 1`** (correct: the in-memory runtime
  tick loop must not be double-ticked), DB-free `HEALTHCHECK`.
- **nginx** — HTTP→HTTPS 301 redirect, TLS1.2/1.3 + `HIGH:!aNULL:!MD5`, HSTS,
  websocket upgrade with long timeouts, immutable static caching,
  `client_max_body_size 10M`.
- **systemd hardening** — `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict`,
  `ProtectHome`, scoped `ReadWritePaths`, `LimitNOFILE/NPROC`.
- **`deploy_production.sh`** has `set -e` and aborts on placeholder secrets in
  `.env`; backup/restore scripts have `set -e`.

## Deliberately deferred

- Unify the gunicorn worker-class across Dockerfile / both systemd units (needs
  a runtime call on eventlet vs gevent-websocket; behaviour-equivalent today).
- Compose `read_only` rootfs + `cap_drop: [ALL]` — deeper container hardening;
  diminishing returns given non-root + no-new-privileges.

## Resolution summary

**Fixed (verified: `docker-compose config` validates with env set, fails closed
without; configs reviewed):**

- **D1** compose secrets fail-closed (`:?`); **D2** postgres host port removed
  (internal-only `expose`); **D3** compose healthcheck → `/api/runtime/health`;
  **D4** `no-new-privileges` on all services + dropped obsolete `version:`;
  **D5** `tablewars.service` `StartLimit*` moved to `[Unit]`; **D6** nginx
  `Referrer-Policy`.

**Deferred / rejected** — worker-class unification, nginx per-IP rate limiting
(would break NAT'd pucks), `deploy_all_pucks.sh` `set -e` (would break its
intentional continue-on-failure), with rationale above.
